# Weekly Lab Submission Instructions

These instructions are the same for each weekly lab. Only the **week number** and the corresponding lab assignment change.

## Before you start

You need **one fork of the course repository for the entire semester**:

`https://github.com/ValRCS/RBS_BS0030_Programming_Languages`

Do **not** create a new fork or a new repository for every lab. Continue working in the same fork each week.

Before starting a new lab, make sure your fork/local copy is reasonably up to date with the course repository.

## Lab task

The actual programming task for each week is published in that week's `assignment.md` file in the public course repository.

For example, Week 3 uses:

`labs/week03/assignment.md`

For later weeks, use the corresponding week directory, for example `labs/week04/assignment.md`, `labs/week05/assignment.md`, and so on.

Follow the requirements in that week's `assignment.md` and place your work in the locations specified there.

## What you must do before submitting

1. Complete as much of the week's assignment as you can.
2. Make sure your work is saved inside your forked repository.
3. Commit your changes with a meaningful commit message.
4. Push the commit(s) to GitHub.
5. Open your fork on GitHub and verify that the files you intend to submit are visible there.

Your GitHub repository should contain the work itself. Moodle is used to submit the repository link and your short report.

## What to submit in Moodle

For **every weekly lab**, submit the following two items.

### 1. Link to your forked GitHub repository

Submit the URL of your fork, for example:

`https://github.com/YOUR-USERNAME/RBS_BS0030_Programming_Languages`

Normally this will be the **same repository URL every week**. You are submitting it again so that each Moodle lab assignment has an explicit submission associated with that week.

Do not submit only a Codespace URL or a local filesystem path. The instructor must be able to open the repository on GitHub and inspect the committed work.

### 2. Short work report

Add a short write-up describing your work for the current week. A few sentences or bullet points are sufficient.

Include:

- what you completed;
- the main files or parts of the assignment you worked on;
- anything that is incomplete;
- blockers, technical problems, or concepts that caused difficulty;
- optionally, any specific question you would like the instructor to look at.

Example:

> Completed Tasks 1-3 and most of Task 4. My work is in `labs/weekXX/work/`. The main difficulty was understanding how the language handles immutable data. Task 4 is incomplete because I could not get the final test case to pass.

A blocker is not automatically a problem with the submission. Describing where you got stuck is useful information and is preferable to leaving unfinished work unexplained.

## Important submission rules

- Use **one fork for the whole course**.
- Submit the **same fork URL each week**, after pushing that week's work.
- Your work must be **committed and pushed**; uncommitted local or Codespaces changes cannot be assessed.
- Keep the course directory structure unless the week's `assignment.md` explicitly tells you otherwise.
- Do not replace the repository submission with screenshots, pasted source code, or ZIP files unless specifically requested.
- The week-specific requirements in `assignment.md` take precedence if they differ from these generic submission instructions.

## Quick checklist

Before pressing **Submit** in Moodle, verify:

- [ ] I used my existing course fork.
- [ ] I completed the current week's `assignment.md` tasks as far as possible.
- [ ] I committed my work.
- [ ] I pushed the commits to GitHub.
- [ ] I checked that the work is visible in my GitHub fork.
- [ ] I submitted the fork URL in Moodle.
- [ ] I included a short summary of completed work and any blockers.
